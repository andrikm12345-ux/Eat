# Переезд на Cloudflare одним шагом

Дневник сейчас работает на **Netlify**. Если там закончатся кредиты (сайт встанет на паузу до
начала следующего месяца), его можно за несколько минут поднять на **Cloudflare Workers**. Всё
для этого уже подготовлено в ветке `cloudflare`, ничего не запущено.

## Состояние на 27.11.2026

- В Cloudflare создан Worker **`eat`** как **заглушка** (отвечает «not launched», публичного адреса
  `workers.dev` нет). Приложение в него **не выложено**.
- В него **уже внесены секреты** (взяты из Netlify): `AUTH_SECRET`, `KV_REST_API_URL`,
  `KV_REST_API_TOKEN`, `BACKUP_KEY`, `ADMIN_LOGINS`, `AI_API_KEY`, `AI_MODEL_TEXT`, `AI_MODEL_VISION`.
  Если на Netlify значение изменится, его надо обновить и в Cloudflare. `SCRYPT_COST` задаётся
  из `wrangler.jsonc` при выкладке, вносить не надо.
- Подключения к GitHub у этого Worker'а **нет** (его надо создать в момент переезда, см. ниже).

## Настройки сервера тоже в копиях

Каждая ночная копия содержит ещё и **настройки сервера** (ключи и токены: `AUTH_SECRET`, токен
Upstash, ключ ИИ и другие, но **не** сам `BACKUP_KEY`) отдельным файлом `env_.json`, зашифрованным
`BACKUP_KEY`. Прочитать его можно на своём компьютере: `BACKUP_KEY=... node scripts/open-backup.mjs
data/<день>/env_.json` (папку `backups` скачать с GitHub). Кнопка «Restore» эти настройки **не**
возвращает: в базу они не пишутся, их вносят в хостинг вручную. **`BACKUP_KEY` из копий не
достать, его нужно хранить отдельно у себя.**

## Что уже готово

| Что                             | Где                                                                                                    | Состояние                            |
| ------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------ |
| Серверная часть для Cloudflare  | `cloudflare/worker.ts` (тот же маршрутизатор `/api/*`, что на Netlify)                                 | написана, проверена локально         |
| Настройки Cloudflare            | `wrangler.jsonc` (страницы из `dist`, `/api/*` в Worker, `keep_vars`)                                  | готовы                               |
| Защитные заголовки              | `public/_headers` (те же, что в `netlify.toml`)                                                        | готовы                               |
| **Данные пользователей**        | Upstash Redis (общий для любого хостинга)                                                              | **переносить не нужно**              |
| **Резервные копии**             | GitHub, ветка `backups`, шифруются `BACKUP_KEY`                                                        | **переносить не нужно**              |
| Копии при паузе основного сайта | `backup.yml` пробует второй адрес `SITE_URL_FALLBACK`                                                  | готово (задать переменную, см. ниже) |
| Пароли при переезде             | цена хэша `SCRYPT_COST=4096` только на Cloudflare, старые пароли подходят и сами обновляются при входе | готово                               |

Данные и копии живут отдельно от хостинга, поэтому «переехать» значит только перенести
**переменные** и **переключить адрес**.

## Что сделать заранее (один раз, не мешает работе)

1. **Cloudflare → Workers & Pages → `eat` → Settings → Build** (или Builds): отключите
   автоматическую сборку из `main` (Pause / Disable builds). Иначе каждый пуш в `main` будет
   выкладываться и туда. Пока выключено, ничего не запускается.
2. **Cloudflare → `eat` → Settings → Variables and Secrets**: добавьте переменные из таблицы ниже.
   Секреты вносите с типом _Secret_. Значения берите из Netlify (Site configuration →
   Environment variables → значок «копировать» у нужной строки Production). Ничего не вставляйте в
   чат и в репозиторий.
3. **GitHub → репозиторий → Settings → Variables → Actions**: добавьте переменную
   `SITE_URL_FALLBACK` = адрес Cloudflare-сайта (вида `https://eat.<ваш-поддомен>.workers.dev`,
   он виден в карточке Worker). Тогда ежедневные копии пойдут туда, даже если Netlify на паузе.
   Это работает, только когда Cloudflare уже запущен (до этого копии идут с Netlify как обычно).
4. Запишите в заметку рядом с `BACKUP_KEY`: адрес Cloudflare-сайта.

### Переменные (имена такие же, как в Netlify)

| Имя                                                                 | Тип            | Откуда значение                                                  |
| ------------------------------------------------------------------- | -------------- | ---------------------------------------------------------------- |
| `AUTH_SECRET`                                                       | Secret         | из Netlify, **точно такое же** (иначе все аккаунты «потеряются») |
| `KV_REST_API_URL`                                                   | Plain          | из Netlify (адрес Upstash)                                       |
| `KV_REST_API_TOKEN`                                                 | Secret         | из Netlify (токен Upstash)                                       |
| `BACKUP_KEY`                                                        | Secret         | из Netlify (тот же ключ, что в вашей заметке)                    |
| `ADMIN_LOGINS`                                                      | Plain          | из Netlify                                                       |
| `AI_API_KEY`                                                        | Secret         | из Netlify (если задан)                                          |
| `AI_BASE_URL`, `AI_MODEL_TEXT`, `AI_MODEL_VISION`, `AI_DAILY_LIMIT` | Plain          | из Netlify (если заданы)                                         |
| `SEARCH_API_KEY`, `SEARCH_DAILY_LIMIT`                              | Secret / Plain | из Netlify (если заданы)                                         |
| `SIGNUP_DISABLED`, `USER_LABELS`                                    | Plain          | из Netlify (если заданы)                                         |
| `SCRYPT_COST`                                                       | Plain          | уже указан в `wrangler.jsonc` (4096), вносить не надо            |

Лишнее не нужно: `KNOWN_LOGINS` удалена, `RESTORE_UNTIL` и `AI_BUDGET_MS` на Cloudflare не нужны.

## Переезд (когда понадобится), по шагам

0. В Cloudflare: Workers & Pages → `eat` → Settings → Build (Git connection) → подключите репозиторий
   `andrikm12345-ux/Eat`, ветка `main`, команда сборки `npm run build`, команда выкладки
   `npx wrangler deploy`. Переменные при этом сохранятся (`keep_vars`).
1. Влейте ветку `cloudflare` в `main` (на GitHub: Pull requests → New → `cloudflare` → Merge).
   Netlify при этом соберётся только если изменился код сайта. Если Netlify уже на паузе, это не
   страшно.
2. В Cloudflare включите сборку из `main` (или нажмите _Deploy_/_Retry deployment_). Через пару
   минут сайт поднимется на `https://eat.<поддомен>.workers.dev`.
3. Проверьте адрес: открывается страница, вход вашим логином работает, в «Аккаунт» видна
   синхронизация, на «Сегодня» ваши данные.
4. Скажите людям новый адрес. Каждому нужно один раз открыть его и **войти заново** своим
   логином и паролем (данные подтянутся из облака). Фото, которые хранятся только на устройстве,
   и записи, не успевшие синхронизироваться на старом адресе, не переносятся: перед переездом
   попросите нажать «Синхронизировать сейчас» в «Аккаунт».
5. В GitHub Variables поменяйте `SITE_URL` на новый адрес (а `SITE_URL_FALLBACK` можно убрать).
   Запустите Actions → Backup → _Run workflow_ и убедитесь, что он зелёный.
6. Старый сайт на Netlify можно оставить (до паузы он просто отвечает), данные общие.

## Откат

Данные общие, поэтому обратно переезжать так же просто: адрес Netlify продолжает работать (когда
кредиты вернутся) и входы там те же. Пароли, обновлённые на Cloudflare, на Netlify тоже
подходят и сами вернутся к полной цене при входе.

## Что нужно знать

- **Лимит Cloudflare Free: 10 мс процессорного времени на запрос.** Полная цена хэша пароля
  (~45 мс) туда не помещается, поэтому на Cloudflare включено `SCRYPT_COST=4096` (~10 мс). Это
  безопаснее, чем пароль без защиты, но слабее полного. Вход самого первого раза у каждого
  человека использует старый «тяжёлый» хэш и может один раз не пройти (ошибка 1102): тогда
  повторить вход. Если ошибок много, нужен платный тариф Workers (5 долларов в месяц) либо
  вход придётся оставить на другом хостинге. Заранее это не проверялось на настоящем Cloudflare,
  только в локальном запуске (`wrangler dev`).
- **Лимит запросов Cloudflare Free:** 100 000 в сутки на API; страницы и файлы не считаются.
- Задержка и лимит ИИ-запросов: на Cloudflare нет ограничения в 60 секунд Netlify, но `AI_BUDGET_MS`
  по умолчанию 90 секунд.
- Подключение своего домена (если когда-нибудь появится) позволит переезжать без нового адреса
  для людей: меняется только то, на какой хостинг он указывает.
