# Дневник

Личный offline-first PWA-трекер питания и веса для одного пользователя. Бэкенда нет: все данные хранятся
локально в IndexedDB на устройстве. Интерфейс на русском, mobile-first. ИИ (Claude API) — необязательная
надстройка: всё, кроме распознавания фото, текста и этикеток и недельных ИИ-наблюдений, работает без сети и без ключа.

Продакшен: https://dnevnik-theta.vercel.app

## Возможности

- **Сегодня** — кольцо калорий, БЖУ и клетчатка, тренд веса со взвешиванием на цифровой клавиатуре, поток дня
  (стопки ≤ 30 мин, свайпы удалить/повторить с Undo, долгий тап — время, перенос, шаблон, копия), активность,
  вода, баннеры-напоминания, серия записей.
- **Добавление** — поиск по каталогу (ё/е, раскладка, опечатки), «частые в это время» (3 тапа), штрихкод
  (BarcodeDetector / ZXing → Open Food Facts), фото / текст / этикетка через ИИ, быстрые ккал, рецепты (с уваркой),
  шаблоны, повтор и копирование дня. Всё внешнее проходит через единый экран проверки.
- **Дневник** — календарь с нейтральной раскраской по цели _того_ дня.
- **Прогресс** — график веса (сырые точки + EMA-тренд), путь к целевому весу с прогнозом, замеры и % жира
  (ВМС США), фото прогресса, адаптивный расход энергии.
- **Отчёты** — недельный разбор, график адаптивного TDEE с полосой неопределённости, микронутриенты
  с покрытием данных, необязательные ИИ-наблюдения (только агрегаты).
- **Цели** — мастер цели с объяснением, еженедельный пересчёт (check-in) с ограничениями ±200 ккал и
  безопасным минимумом, ручные цели с датой начала действия.
- **Данные** — экспорт/импорт JSON (заменить / слить), CSV-экспорт, CSV-импорт веса, шагов и тренировок,
  напоминание о резервной копии, статус хранилища.
- **Мягкая геймификация** — серии с заморозками, ~25 достижений, напоминания через `.ics`, число на иконке.

## Разработка

```bash
npm ci          # Node >= 22.12
npm run dev     # http://localhost:5173 (service worker в dev выключен)
npm run lint    # ESLint + Prettier
npm test        # Vitest; для src/domain обязательное покрытие 100 % веток
npm run build   # tsc + vite build + проверка бюджета главного бандла (≤ 300 КБ gzip)
npm run preview # прод-сборка локально, с service worker
```

> Установка **новых** зависимостей: npm 10 падает на внутренней ошибке arborist при разрешении peer-зависимостей
> vitest. Используйте `npx npm@11 install -E <пакет>`; `npm ci` по lock-файлу работает и на npm 10.

Вспомогательные скрипты:

- `npm run icons` — генерирует геометрические PNG-иконки без зависимостей (результат закоммичен).
- `node scripts/build-base-foods.ts <sr_legacy.json>` — собирает базовый каталог (`src/data/baseFoods.json`)
  из USDA FoodData Central SR Legacy (общественное достояние). Список продуктов с русскими названиями —
  `scripts/base-foods-map.ts`. Id продуктов (`base-<fdcId>`) должны оставаться стабильными.

## Деплой на Vercel

`vercel.json` уже настроен: SPA-rewrites, `sw.js` и manifest без кэша, `assets/` — immutable.


## Установка на телефон

**iPhone (Safari):** откройте сайт → «Поделиться» → «На экран Домой». Запускайте с иконки — приложение откроется
без адресной строки и будет работать офлайн. Данные установленного приложения хранятся отдельно от Safari:
удаление иконки стирает данные, поэтому периодически делайте экспорт (Ещё → Импорт и экспорт).

**Android (Chrome):** меню ⋮ → «Установить приложение». Долгое нажатие на иконку открывает ярлыки
«Добавить еду», «Вес», «Сканер».

После первого открытия дождитесь сообщения «Приложение готово к работе без сети». Новые версии приходят
баннером «Доступно обновление».

### ИИ

Ещё → ИИ-настройки: включите ИИ, вставьте API-ключ Anthropic (хранится только на устройстве, не попадает
в экспорт), при первом использовании подтвердите отправку данных. Модели по умолчанию: `claude-haiku-5-5`
для текста, `claude-sonnet-5-5` для фото и разборов (можно поменять). Запросы идут напрямую из браузера.

### Напоминания

PWA на iPhone не может надёжно получать push без сервера, поэтому: баннеры при открытии, файл `.ics`
с повторяющимися событиями для системного календаря (Ещё → Напоминания) и уведомления, пока приложение открыто.

## Структура

```
src/domain     чистые функции: формулы, тренд, TDEE, макро, поиск, отчёты (100 % тестов)
src/db         Dexie (схема v1), репозитории, хуки
src/ai         клиент Claude, промпты, валидаторы, оркестрация
src/services   сценарии поверх БД: записи, OFF, рецепты, TDEE, бэкап, геймификация
src/features/* экраны
src/ui         общие компоненты
src/i18n/ru.ts все тексты интерфейса
```

## Решения и отклонения от ТЗ

- **Адаптивный TDEE.** Изменение запасов в окне считается по линии регрессии через взвешивания окна,
  а не как разность EMA-тренда: у EMA есть стартовое запаздывание, из-за которого критерий
  «ошибка < 150 ккал за 28 дней» недостижим. Коэффициент сглаживания сначала работает как скользящее
  среднее (1/(n+2)) и опускается до 0,1 × доля валидных дней. Остальное — по ТЗ. Симуляция
  (истинный TDEE 2600, старт 2200, шум ±0,8 кг): без шума ошибка < 150, медиана 61 ккал, > 85 % прогонов < 150.
- **Шаблоны.** `TemplateItem` хранит `name` рядом со снимком `snapshot: Nutrients`
  (тип `Nutrients & {name: string}` невыразим в TypeScript из-за индексной сигнатуры).
- **Фото в экспорте** кладутся в JSON как base64 (по желанию), без отдельного ZIP.
- **Жиры по умолчанию** — 25 % калорий; белок при известной безжировой массе удерживается в 2,3–3,1 г/кг LBM.
- **Тренд**: тест «шум ±1 кг → отклонение < 0,3 кг» проверяет среднее отклонение (максимум на случайном
  шуме при α = 0,1 доходит до ~0,45 кг).

## Аккаунт и синхронизация

Логин и пароль (экран «Ещё → Аккаунт и синхронизация»), без почты. Данные (без фото и ключа ИИ) сливаются с облачной копией по `updatedAt`.

- Сервер: `api/` (Vercel Functions) + `server/` (логика). Пароль хранится только как хэш scrypt с солью (`creds/<id>.json`), копия данных — `users/<id>.json`, оба в приватном Vercel Blob. Сессия — подписанный токен на 180 дней.
- Защита: 5 неверных паролей подряд блокируют вход на 15 минут, неизвестный логин отвечает так же, как неверный пароль.
- Восстановление: при создании аккаунта показывается одноразовый код восстановления (хранится только его хэш). Экран «Забыли пароль?» принимает логин + код и задаёт новый пароль; после этого выдаётся новый код. Аккаунты, созданные до появления кодов, восстановить нельзя.
- Переменные окружения Vercel: `AUTH_SECRET` (≥32 символов), `BLOB_READ_WRITE_TOKEN` (создаётся хранилищем), необязательно `SIGNUP_DISABLED=1` (закрыть регистрацию, существующие аккаунты работают).
