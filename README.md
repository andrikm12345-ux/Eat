# Дневник

Личный дневник питания и веса: PWA на русском, mobile-first, работает без сети, данные хранятся на
устройстве и синхронизируются с аккаунтом (логин и пароль, без почты). Есть общий ИИ для распознавания
еды по описанию и фото.

- Продакшен: https://dnevnik-theta.vercel.app
- Деплой: пуш в `main` автоматически выкладывается на Vercel (остальные ветки — превью).
- Этот README написан так, чтобы по нему можно было **собрать всё с нуля** до нынешнего состояния:
  разделы «Как собрать с нуля» и «Внешние сервисы» — для этого; остальное — справка о том, как всё
  устроено и почему.

## Что умеет приложение

Пять вкладок внизу (Сегодня, Дневник, Прогресс, Отчёты, Ещё) и круглая «+» над панелью.

- **Сегодня** — небесная карточка дня (небо меняется по времени суток, сезонные листья/снег/лепестки):
  приветствие, серия записей, калории и БЖУ, линия дня с приёмами пищи, остаток калорий и одна кнопка
  «Добавить завтрак/обед/…». Ниже: поток дня (стопки записей ≤ 30 мин, свайпы, действия), «Чем добрать
  норму» (идеи из ваших привычных продуктов под остаток калорий и белка), вес, вода, активность.
- **Добавление** (кнопка «+») — поиск по каталогу (ё/е, раскладка, опечатки, формы слов), штрихкод
  (BarcodeDetector / ZXing → Open Food Facts), **описать словами** (ИИ), **фото** (ИИ), быстрые ккал,
  повтор, шаблон, рецепт. Всё внешнее проходит через единый экран проверки.
- **Дневник** — календарь месяца на небе, цвет дня по цели _того_ дня, список дней.
- **Прогресс** — вес и цель на небе, линия тренда, график с EMA, путь к цели и прогноз, замеры, фото.
- **Отчёты** — неделя (7 столбиков калорий), расход энергии (адаптивный TDEE), микронутриенты,
  необязательные ИИ-наблюдения.
- **Ещё** — имя и серии, плитки: продукты, рецепты, шаблоны, профиль и цели, тренировки, достижения,
  напоминания, ИИ-настройки, аккаунт, данные, хранилище, о приложении.
- **Цели** — мастер цели с объяснением, еженедельный пересчёт (check-in) с ограничениями ±200 ккал и
  безопасным минимумом, ручные цели с датой начала действия.
- **Данные** — экспорт/импорт JSON, CSV-экспорт, CSV-импорт веса/шагов/тренировок.
- **Мягкая геймификация** — серии с заморозками, ~25 достижений, напоминания через `.ics`, число на иконке.
- **Свайп вправо** на любом внутреннем экране — «назад» (стрелка у края экрана).
- **Администратор** (по списку логинов) — просмотр пользователей и их дневников (только чтение, с журналом).

## Стек

Vite 8 · React 18 · TypeScript (strict) · React Router 7 · Zustand · Dexie (IndexedDB) ·
vite-plugin-pwa (Workbox) · CSS Modules · Vitest + Testing Library · ESLint + Prettier.
Сервер: Vercel Functions (Node) + приватный Vercel Blob. Ошибки: Sentry SDK → Better Stack.
Node ≥ 22.12.

## Быстрый старт

```bash
npm ci          # Node >= 22.12
npm run dev     # http://localhost:5173 (service worker в dev выключен)
npm run lint    # ESLint + Prettier
npm test        # Vitest; для src/domain обязательное покрытие 100 %
npm run build   # tsc -b + vite build + проверка бюджета (≤ 300 КБ gzip главного бандла)
npm run preview # прод-сборка локально
```

> Установка **новых** зависимостей: npm 10 падает на внутренней ошибке arborist из-за peer-зависимостей
> vitest. Используйте `npx npm@11 install -E <пакет>`; `npm ci` по lock-файлу работает и на npm 10.
> Версии в `package.json` закреплены точно (без `^`).

Локально серверная часть (`/api/*`) не запускается: вход, синхронизация и ИИ работают только на Vercel
(или через `vercel dev`). Всё остальное (каталог, дневник, вес, отчёты) работает без сервера.

Скрипты:

- `npm run icons` — рисует иконки, favicon и заставки запуска iPhone (`scripts/gen-brand.cjs`; нужен
  Playwright с Chromium; результат закоммичен в `public/`).
- `node scripts/build-base-foods.ts <sr_legacy.json>` — собирает базовый каталог
  (`src/data/baseFoods.json`) из USDA FoodData Central SR Legacy (общественное достояние).
  Русские названия — `scripts/base-foods-map.ts`. Id продуктов (`base-<fdcId>`) должны быть стабильны:
  на них ссылаются записи.

## Устройство кода

```
src/domain      чистые функции: формулы, тренд, TDEE, макро, поиск, разбор текста, отчёты (100 % тестов)
src/db          Dexie (схема v1), репозитории, хуки, загрузка каталога
src/ai          клиент ИИ, подсказки, проверка ответа, настройки
src/services    сценарии поверх БД: записи, разбор описания, память, OFF, рецепты, TDEE, бэкап,
                синхронизация, геймификация, интернет-поиск, отчёт об ошибках
src/features/*  экраны (today, add, diary, progress, reports, more, review, ai, …)
src/ui          общие компоненты: Page, BackBar, BottomNav, Fab, BottomSheet, kit (Card, Button, поля),
                sky/ (небо), useSwipeBack, motion
src/state       Zustand: выбранный день, окно «Добавить», черновик проверки, всплывающие сообщения
src/i18n/ru.ts  все тексты интерфейса (русский)
src/data        базовый каталог: baseFoods.json (USDA) и ruFoods.json (привычные русские блюда)
src/styles      tokens.css (цвета, размеры), global.css, fonts.css
api/*           тонкие входы Vercel Functions
server/*        логика сервера (авторизация, синхронизация, ИИ, поиск, админка)
scripts/*       иконки, сборка каталога, проверка бюджета бандла
docs/           справки (docs/AI-RAKETA.md — сохранённые настройки ИИ)
```

Ключевые договорённости:

- Все пользовательские тексты только в `src/i18n/ru.ts`. Числа с единицами пишутся через неразрывный
  пробел (` `), кавычки в русских строках — ёлочки; это проверяет тест типографики.
- Цвета, размеры, отступы, тени — только переменные из `tokens.css`. Для светлой и тёмной темы есть
  отдельные значения.
- Каждая вкладка и внутренний экран строится на общем `Page`: на вкладках сверху небо (`SkyHeader`),
  на внутренних — полоска неба с круглой кнопкой «назад» (`BackBar`).
- Домен не знает про React и браузер; всё, что считает числа, лежит в `src/domain` и покрыто тестами.

## Данные и синхронизация

IndexedDB через Dexie, схема v1 (`src/db/db.ts`): `profile`, `goals`, `foods`, `recipes`, `templates`,
`entries`, `dayMeta`, `weights`, `measurements`, `workouts`, `tdeeHistory`, `checkins`, `achievements`,
`aiRuns`, `blobs` (фото), `settings`. Будущие версии схемы — только через `version(n).stores().upgrade()`
и после экспорта копии.

- Каждая запись имеет `id` (ULID), `createdAt`, `updatedAt`, `deletedAt` (мягкое удаление).
- Запись дневника хранит **снимок** питательных веществ на момент записи: позднее изменение продукта
  не меняет прошлые дни.
- Настройки (`settings`) — пары ключ/значение; ключи секретов и ключи, начинающиеся с `ai`, не уходят в облако.
- **Синхронизация**: двустороннее слияние с облачной копией по `updatedAt` (`src/services/sync.ts`);
  фото и ключи ИИ в облако не отправляются. Облачная копия — один JSON-файл на пользователя.
- Резервная копия: экспорт/импорт JSON (заменить / слить), перед заменой автоматически сохраняется копия
  текущих данных.
- «Память описаний» (`settings.mealMemory`) — до 400 последних фраз, которые вы описывали и сохраняли;
  синхронизируется вместе с настройками.

## Сервер

Vercel Functions, **11 из 12** возможных на тарифе Hobby (лимит платформы — не добавляйте функции без
необходимости; новые маршруты складывайте в существующие). Тонкие входы в `api/`, вся логика в `server/`:

| Маршрут                                                       | Назначение                                                        |
| ------------------------------------------------------------- | ----------------------------------------------------------------- |
| `api/auth/register`, `login`, `password`, `recovery`, `reset` | аккаунты                                                          |
| `api/sync`                                                    | получить/отправить облачную копию; заголовок `x-ui-labels`        |
| `api/ai/chat`, `status`, `config`                             | общий ИИ: прокси к сервису, доступность, настройки администратора |
| `api/search`                                                  | интернет-поиск для справки ИИ (Tavily)                            |
| `api/admin`                                                   | список пользователей и их дневников (только чтение)               |

Хранилище: приватный Vercel Blob (`creds/<id>.json` — хэш пароля scrypt с солью, `users/<id>.json` —
данные, `usage/…` — суточные счётчики, `config/ai.json` — настройки ИИ администратора, `audit/…` — журнал
просмотров администратора).

Безопасность: сессия — подписанный токен на 180 дней; неизвестный логин отвечает как неверный пароль;
неверные попытки считаются на аккаунт и на адрес, после 8 — блокировка на 15 минут; код восстановления
показывается один раз (хранится только хэш); заголовки CSP, `X-Frame-Options`, `Permissions-Policy`
заданы в `vercel.json`. `api/ai/chat` может работать до 90 секунд (`functions` в `vercel.json`).

## ИИ

Один общий ИИ для всех пользователей: ключ **только на сервере** (переменные Vercel), приложение шлёт
запросы на `/api/ai/chat` с токеном сессии. У каждого пользователя дневной лимит (по умолчанию 60,
у администратора нет). Можно вписать и свой ключ (Ещё → ИИ-настройки) — тогда запросы идут напрямую.

- Сервис и модель по умолчанию: TokenHarbor (`https://tokenharbor.ai/v1`, формат OpenAI),
  модель `mimo-v2.6-flash:free`. Заменяется переменными `AI_BASE_URL`, `AI_MODEL_TEXT`,
  `AI_MODEL_VISION` или администратором в приложении.
- К запросу добавляются флаги «не думай» (`reasoning_effort`, `thinking`, `enable_thinking`, …): при
  ответе 400/422 запрос повторяется без них. Потолок ответа 4000 токенов (текст) / 6000 (фото).
  Ожидание: 87 с на сервере, 92 с в приложении.
- **Модель медленная и разной скорости** (от 5 до 90 секунд). Поэтому весь пользовательский путь построен
  так, чтобы ИИ не мешал: смотрите «Описать словами» ниже.
- Сохранённая рабочая версия настроек — «Ракета» (ветка `ai-raketa`, описание в `docs/AI-RAKETA.md`).
  Если что-то поменяли и ИИ стал тупить, верните её.

### «Описать словами» (`src/services/mealParts.ts`)

1. Текст режется на фрагменты (`src/domain/mealText.ts`): запятые, «и», «+»; десятичная запятая не разделяет;
   добавки («мёдом», «с сахаром») приклеиваются к блюду; поддержаны слова-числа, «пол», «пару», «ложка»,
   «стакан без числа = один», марки с «и» («Вкусно и точка»).
2. **Память**: фразы, которые вы уже сохраняли, возвращаются сразу с вашими цифрами (пересчитываются на
   количество). Показывается пометка «как в прошлый раз».
3. **Каталог**: фрагмент с количеством, найденный в базе (схожесть ≥ 0,8; без количества ≥ 0,95).
4. Остальное уходит ИИ **вместе с полной фразой** и списком уже посчитанного. Интернет-справка
   (Tavily, до 3 результатов по 350 символов) ищется только для марок, магазинов и кафе
   (латиница, кавычки, слово с большой буквы или название из списка `CHAINS`).
5. Если ИИ не отвечает за 20 секунд, показывается быстрый результат по каталогу, а когда ИИ закончит —
   всплывает сообщение «ИИ закончил» и кнопка «Показать оценку ИИ».
6. Ответ ИИ приводится в порядок (`cleanName`: убирает количество из названия, латинские буквы-двойники),
   названия сверяются с каталогом, вес штуки берётся из каталога, если он там есть.
7. На экране проверки человек правит цифры; при сохранении запоминаются исправленные продукты и фразы.

Тип приёма пищи **не берётся из догадки ИИ** (ИИ видит только еду, но не время): приём определяется по
времени записи.

### Фото

`src/features/ai/AiPhotoPage.tsx`: фото сжимаются до 1024 px (768, если их несколько), качество 0,72.
Один экран для готового блюда и таблицы пищевой ценности на упаковке.

### Быстрый разбор без ИИ (`src/services/localMeal.ts`)

Тот же разбор фраз, но только по каталогу и Open Food Facts. Слабые совпадения отбрасываются, зерновые без
слова «крупа» берутся варёными.

### Каталог

`baseFoods.json` (USDA, 400+ продуктов с русскими названиями) и `ruFoods.json` (привычные русские блюда:
борщ, плов, пельмени, сырники, оливье, творог, кефир, капучино, самса и др.). Версии каталога
складываются; значения калорий проверяются на согласие с БЖУ.

## Оформление

- **Небо**: `src/ui/sky/` и `src/features/today/scene.ts` — цвета неба по времени суток (интерполяция
  по ключевым точкам), звёзды ночью, сезонные частицы (листья осенью, снег зимой, лепестки весной,
  светлячки летом ночью) и «земля» по нижнему краю. Верх каждой вкладки — `SkyHeader`.
- **Цветные карточки**: тона `food`, `weight`, `water`, `activity`, `sun`, `rose`, `sand`, `mint`, `sky`
  (переменные `--tone-*` в `tokens.css`; карточка без тона берёт следующий по кругу).
- **Нижняя панель**: «парящая», в цвета неба; активная вкладка — зелёная «таблетка»; кнопка «+» парит по
  центру над панелью (`BottomNav` + `Fab`).
- **Кнопки**: главные — светло-зелёные «пилюли», второстепенные — белые с тенью (`--btn-main`, `--btn-soft`).
- **Окна снизу** (`BottomSheet`) — с полоской неба в шапке.
- **Иконка**: закатное небо, листья, зелёная тарелка с вилкой и ножом (`npm run icons`).
- Анимации отключаются системной настройкой «уменьшить движение».

## PWA и iPhone

- Service worker: Workbox, `registerType: 'prompt'` (баннер «Доступно обновление»), `navigateFallback` на
  `index.html`; `sw.js` и манифест отдаются без кэша, `assets/` — `immutable`.
- Установка: iPhone — Safari → «Поделиться» → «На экран Домой»; Android — меню ⋮ → «Установить».
  Данные установленного приложения живут отдельно от Safari.
- Ярлыки иконки (Android): «Добавить еду», «Вес», «Сканер».
- Напоминания: iPhone не даёт надёжных push без сервера, поэтому — баннеры при открытии, файл `.ics` для
  календаря и уведомления, пока приложение открыто.
- Масштабирование щипком и двойным касанием отключено (`src/ui/noZoom.ts`).
- Цвет полосы браузера (`theme-color`) следует за небом на текущем экране.

## Тесты и качество

- `npm test` — Vitest (jsdom, `fake-indexeddb`); около 590 тестов. Для `src/domain` порог покрытия 100 %.
- `npm run lint` — ESLint (без предупреждений) + Prettier. Запрещены `!` (non-null) и удаление по
  динамическому ключу; шаблонные зависимости хуков проверяются.
- `npm run build` — `tsc -b` ловит то, что не ловит `tsc --noEmit`; затем проверка бюджета главного
  бандла (≤ 300 КБ gzip; сейчас ≈ 199 КБ).
- Привычка: **сначала зелёные тесты, потом коммит и пуш** (пуш в `main` сразу выкладывает).
- Проверка вида — снимки Playwright на 390 и 360 px в светлой и тёмной теме.
- Описание словами проверялось на наборе из ~50 фраз без ИИ и 26 фраз против живого ИИ (калории
  сравнивались с таблицами). Такой прогон стоит повторять после правок разбора и подсказок.

| `SIGNUP_DISABLED`                                 | нет         | `1` — закрыть регистрацию                                                   |
| `USER_LABELS`                                     | нет         | личный текст кнопки «Взвеситься» для отдельных логинов                      |
| `VITE_SENTRY_DSN`                                 | нет         | включает отчёты об ошибках (попадает в сборку)                              |

> **`AUTH_SECRET` — самое важное значение.** Из него считаются идентификаторы пользователей (они же имена
> файлов с данными в облаке). Если собирать проект заново с **новым** секретом, прежние аккаунты и облачные
> данные станут недоступны: все начнут с чистого листа (данные можно вернуть из экспорта JSON). Чтобы
> сохранить аккаунты, при сборке заново нужно подставить **тот же** `AUTH_SECRET` и подключить то же
> Blob-хранилище. Vercel не показывает значение после сохранения, поэтому держите копию в менеджере паролей.

**Ключи никогда не коммитятся и не пересылаются в чатах**: только в переменные окружения Vercel.
Список названий с пояснениями, где взять каждое значение, — в файле [`.env.example`](.env.example).
Если ключ утёк — удалить и выпустить новый.

## Как собрать с нуля

Порядок, в котором всё было построено и в котором его разумно повторять. После каждого этапа — зелёные
тесты, коммит, пуш.

0. **Заготовка.** Репозиторий на GitHub, `npm create vite` (React + TS), строгий TypeScript, ESLint,
   Prettier, Vitest + Testing Library + `fake-indexeddb`, точные версии зависимостей, бюджет бандла в
   `scripts/check-bundle.mjs`, порог покрытия 100 % для `src/domain`. Подключить репозиторий к Vercel.
1. **Основа.** `tokens.css` (цвета, размеры, тени, светлая и тёмная тема), `ru.ts`, роутинг на пяти вкладках,
   Dexie со схемой v1 и репозиториями (ULID, мягкое удаление, снимки питательных веществ), PWA.
2. **Профиль и цели.** Формулы (Миффлин — Сан-Жеор, активность, темп, безопасный минимум, БЖУ,
   % жира по обхватам), мастер цели с объяснением расчёта. Всё — чистые функции с тестами.
3. **Ввод еды и «Сегодня».** Базовый каталог (скрипт из USDA), нечёткий поиск (ё/е, раскладка,
   опечатки), экран порции, быстрые ккал, поток дня, вода, активность.
4. **Штрихкод и Open Food Facts.** BarcodeDetector и запасной ZXing, проверка контрольной цифры, единый
   экран проверки.
5. **Вес и прогресс.** EMA-тренд, график, замеры, фото, путь к цели.
6. **Расход энергии.** Адаптивный TDEE по регрессии через взвешивания, еженедельный пересчёт цели.
7. **Рецепты, шаблоны, тренировки, CSV.**
8. **Отчёты и микронутриенты.**
9. **Геймификация и напоминания** (серии, достижения, `.ics`).
10. **Экспорт/импорт и полировка.**
11. **Аккаунты и облако.** Функции `api/auth/*`, `api/sync`, приватный Blob, слияние по `updatedAt`.
12. **ИИ.** Сначала с ключом пользователя, затем общий ИИ через `api/ai/chat` (ключ на сервере, суточный

    внутренних экранах, свайп «назад», новая иконка.

этапе проверять тесты и собирать `npm run build`.

## Решения и подводные камни

- **Адаптивный TDEE.** Изменение запасов считается по линии регрессии через взвешивания окна, а не как
  разность EMA-тренда: у EMA есть стартовое запаздывание, из-за которого критерий «ошибка < 150 ккал
  за 28 дней» недостижим. Коэффициент сглаживания сначала работает как скользящее среднее (1/(n+2)) и
  опускается до 0,1 × доля валидных дней. Симуляция (истинный TDEE 2600, старт 2200, шум ±0,8 кг):
  медиана ошибки 61 ккал, > 85 % прогонов < 150.
- **Шаблоны** хранят `name` рядом со снимком `snapshot: Nutrients` (тип `Nutrients & {name: string}`
  невыразим из-за индексной сигнатуры).
- **Фото в экспорте** кладутся в JSON как base64 (по желанию), без отдельного ZIP.
- **Жиры по умолчанию** — 25 % калорий; белок при известной безжировой массе удерживается в 2,3–3,1 г/кг.
- **iOS Safari**: не используйте `backdrop-filter` (оставляет тёмные прямоугольники при прокрутке);
  страницу не сдвигайте при свайпе (открывается тёмный фон) — для жеста «назад» рисуется стрелка;
  при смене стилей проверяйте в тёмной теме.
- **Регулярные выражения для русского**: `\b` не работает с кириллицей — используйте
  `(?<!\p{L})` и `(?!\p{L})`.
- **Неразрывные пробелы** в `ru.ts` ломают замены «в лоб»: правьте по регулярным выражениям и
  проверяйте тестом типографики.
- **Vercel Hobby**: максимум 12 функций; логи запросов хранятся около часа; для сравнения времени
  смотрите логи именно **последнего** деплоя.
- **Бесплатные модели ИИ** отвечают медленно и с очередью; бесплатные тарифы других сервисов (проверяли
  UnoRouter, OpenRouter) ограничивают 1 запросом в минуту на аккаунт — для общего ИИ на всех
  пользователей они не годятся основным вариантом.
- **Тип приёма пищи** определяется по времени, а не по догадке ИИ (ИИ не знает времени).
- **Сети и марки по-русски с маленькой буквы** («пятёрочка кафе») не распознаются правилом «слово с
  большой буквы» — они перечислены в `CHAINS` (`src/services/mealParts.ts`). Новую сеть добавляйте туда.
- **Дубли в приложении**, о которых известно (не исправлены): серия показана в нескольких местах; «Хранилище»
  и «Аккаунт» частично пересекаются; четыре копии круглых кнопок «−/+» в разных стилях.

## Эксплуатация

- Выложить: `git push origin main` (Vercel собирает и выкладывает сам).
- Ошибки в браузерах — Better Stack (Errors), включается `VITE_SENTRY_DSN`; события очищаются от
  личных данных (`src/services/errorReport.ts`).
- Логи серверных функций — панель Vercel; запросы к ИИ пишут время, модель, размер и число токенов
  (без текста и без ключа).
- Сменить модель ИИ: переменные `AI_*` или экран администратора (Ещё → ИИ-настройки). Если стало хуже —
  вернуть «Ракету» (`docs/AI-RAKETA.md`).
- Закрыть регистрацию: `SIGNUP_DISABLED=1`.
- Просмотр пользователей: `/admin` (для логинов из `ADMIN_LOGINS`).
- Если приложение показывает старую версию: Ещё → О приложении → «Обновить приложение».
